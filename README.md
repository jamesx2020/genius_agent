# 筑序 工程项目协同 Agent

三个岗位分别登录，使用 DeepSeek + Deep Agents + LangGraph 进行分析协作。业务、会话、审批与任务保存在 SQLite，附件保存在本地。

## 启动

要求 Python 3.12+、uv；修改前端时需要 Node.js 20.19+ 或 22.12+。

```bash
uv sync
uv run python main.py
```

访问 http://127.0.0.1:8000 。前端构建产物已包含在 `web/`，正常运行不需要启动 Node 服务。

## 配置

项目已提供 `.env`，填写：

```dotenv
DEEPSEEK_API_KEY=你的密钥
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-flash
```

模型名可按账号实际可用模型调整；默认使用 OpenAI 兼容接口和非思考模式工具调用。修改 `.env` 后重启服务。密钥只在后端使用，不返回前端、不写入执行日志；`.env` 已加入 `.gitignore`。`.env.example` 保留无密钥配置模板。

其他可配置项：端口、数据目录、模型超时和输出长度、任务时限、Agent 递归限制、会话时间、上传限制、三个初始账号密码。

## 先体验电缆延期闭环

1. 填写 DeepSeek 密钥并启动。
2. 采购登录，点击“发起协同”，提交预填的 PO001 电缆延期案例。
3. 系统先发送采购延期通知，由项目经理 Agent 查询计划并给出工程影响建议，随后停在“待项目经理回复”。
4. 退出后用项目经理登录，打开同一任务，确认现场影响，选择“接受分批交货 / 要求供应商加急 / 从其他来源调货”。加急、调货必须填写最晚到货日期和所需数量。此回复仅明确处理方向，不批准费用。
5. 采购 Agent 按项目经理要求落实货源与报价，再由财务核算费用。缺少报价时，当前任务会直接显示“确认货源和费用”表单，采购填写供应商、数量、承诺到货日期、单价、加急/调货及运费和报价有效期，点击“提交报价，继续处理”；系统会同时保存报价并整理回复，不需要跨页登记或自行写报告。
6. 形成具体方案后，由项目经理批准或填写原因退回采购。批准后后台复核版本和预算，更新本地订单交付计划；增量费用按有效报价扣减预算。
7. 若退回，由采购补充说明后重新生成方案；新流程会再次请项目经理确认处理要求。

任务详情默认只展开当前岗位需要处理的一项操作，原始通知、Agent 分析、引用依据和处理记录均折叠显示。其他岗位待办显示“等待对方处理”，不用代答；项目经理选择处理方向后系统自动整理回复，补充说明可选。

任务详情支持 SSE 和轮询更新。材料价差由程序根据新旧单价及报价数量自动核算，再加服务费用；不要在费用栏重复填材料价差。

不提供预设“分析成功”降级模式：密钥未配置时任务明确失败，填写配置并重启后点击“重试处理”。普通执行失败保留任务与报价，从当前步骤恢复；业务资料版本失效时重新分析审批。

“业务资料”中，项目经理可更新施工计划，采购可更新报价，财务可更新预算。数据修改会递增版本，阻止旧方案继续执行。

## 第一版范围

- **交货延期**：采购告知 → 项目经理 Agent 评估 → 真人项目经理回复工程影响与处理方向 → 采购落实加急或调货报价 → 财务核算 → 费用与方案审批 → 本地订单更新。当前围绕样例订单 PO001。
- 升级前已经创建的任务保留旧流程以兼容检查点；重启后新建任务及“重新分析”使用新的延期通知流程。
- **材料采购**：三岗位分析后，项目经理批准创建采购申请草稿，不自动下单。
- **付款审核**：三岗位分析后，财务确认创建付款申请草稿，不执行付款。草稿中的金额和收款信息还需人工落实。
- 上传文本 PDF、XLSX、TXT、MD、CSV，提取文本作为证据；不支持扫描件 OCR。
- 使用项目样例资料，默认交付日期为 2026 年 11 月。报价过期后，需由采购在“业务资料”中根据真实情况更新，不会自动延长有效期。
- 当前仅一个试点项目、三岗位账号；尚未接入 ERP、邮件、供应商平台、银行或企业 SSO。
- 前端使用 React 和 Vite、自定义 CSS，延续原型布局；暂未引入 Ant Design 组件库。

## 数据与恢复

```text
data/
├── app.db          # SQLAlchemy 业务、任务、用户、审批、工具与审计
├── checkpoints.db  # LangGraph 流程检查点
└── uploads/        # 上传附件
```

单机、单进程后端，后台执行器串行领取 SQLite 任务。禁止使用多个 Uvicorn worker 或多个服务进程共享数据目录。开启 WAL、外键和忙等待；模型调用不持有数据库写事务。

重启时重新领取执行中的任务，依靠检查点恢复。业务记录、审批和执行幂等检查独立于模型上下文。审批方案绑定版本及内容摘要，正式写入重新检查订单、预算和报价版本。两份数据库之间不假设跨库原子性。

当前表结构为 MVP：项目、订单、预算、报价等版本化记录放在 `business_records` 中，包含项目标识与类型；任务、方案、审批、附件和审计使用独立表。实现与精简设计中的逻辑分组对应，后续按业务复杂度拆表。

启动时自动执行 Alembic 迁移并填充缺失的样例数据；已有业务记录不会被覆盖。也可手工升级：

```bash
uv run alembic upgrade head
```

备份时先停止服务，使用 SQLite backup API 或在完全关闭所有连接后复制两个数据库和附件目录。运行期间不要仅复制 `.db` 主文件而遗漏 WAL 数据。

## 开发与验证

```bash
uv run pytest -q
cd frontend
npm ci
npm run build
```

前端开发模式：在 `frontend` 执行 `npm run dev`，Vite 会将 `/api` 代理到 8000 端口。由于后端验证 Origin，日常联调优先构建后在后端同源页面验证。

测试在独立临时数据库中运行，不使用你的密钥、不访问付费模型。覆盖 Deep Agents 实际工具执行循环（本地脚本模型）、三岗位权限、追问恢复、退回重提、审批幂等、预算不足、数据版本冲突、附件与登录安全。

真实 DeepSeek 的三条延期闭环验收及问题修复见 [闭环测试报告](doc/闭环测试报告.md)。自动测试仍使用模型替身；模型、提示词或工具发生变化后，应另跑真实模型复测。
